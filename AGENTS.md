# AutoQuant Agent Guide

## Mission
Own analytical algorithms, fitted methods, forecasting, supervised learning, reusable evidence/artifact generation, and analytical report rendering.

## Owns
- Generator-first analytical contracts, fitted-state interpretation, method-native diagnostics, and report renderers over artifacts.
- Already-published analytical contracts, fitted-state interpretation, method-native diagnostics, and report renderers over artifacts.

## Must Not Own
- Workstation Project/Workflow identity, app state, report-plan/layout orchestration, UI, or Electron runtime.
- Plot/theme primitives that belong in AutoPlots; feature transformations that belong in Rodeo.

## Canonical Suite Context
Read the private Development constitution and Suite State before cross-repo changes. This public package must not absorb private analytical implementations.

## Local Validation
```r
devtools::load_all()
qa_autoquant_package()
devtools::test()
```
Use `devtools::document()` after roxygen changes and `R CMD check` for release validation.

## Runtime and Dependencies
- Package-first R implementation; data.table tabular authority; engine-native fitted state and evidence remain explicit.
- AutoPlots owns reusable visualization; Rodeo owns fitted feature/temporal transforms. Workstation integration follows package qualification.

## Development Invariants
- Define the analytical contract first; compute once, emit comprehensive reusable artifacts, and render without recomputation.
- Preserve method-native differences and typed unavailability; no H2O canonical path, silent refit, or fallback.
- Repair the first divergent layer, add focused regression, and prove restore/application without refit where relevant.

## Git and Safety
- Preserve all unrelated dirty CARMA work. No revert, stage, commit, push, or force-push unless instructed.
- No secrets, machine paths, fake evidence, or false operational closure.
- Stop and ask when analytical semantics, scale policy, or cross-package ownership is genuinely ambiguous.
